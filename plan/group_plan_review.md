## 一句话结论

**骨架是对的，但核心前提在这个数据集上不成立。**

计划的三条原则——问题驱动而非新架构、每人独立挂 baseline、接口先定死——都直接对齐 rubric，不用动。
但计划假设"细胞密集、粘连严重、division 多"，实测是**稀疏、零粘连、分裂只有 18 个、真正的难处是对比度差 60 倍**。所以"错误 → 负责人"那张表要重写，4 个训练模型要砍到 2 个。

而且有一条实测结论直接决定分工：#4 的 LSTM tracker 在这个数据上**没有提升空间**（见 §4）。

| | 01 | 02 |
|---|---|---|
| 帧数 / 分辨率 / 位深 | 92 / 1024×1024 / uint8（max 221） | 92 / 1024×1024 / uint8（max 155） |
| 细胞数/帧（min–max，均） | 20–25，22.4 | 22–31，27.4 |
| 轨迹数 | 28 | 58 |
| **分裂事件** | **5** | **13** |
| GT/SEG 金标准（可算 SEG 的帧） | 30 帧，**全部在 f002–f047** | 20 帧，散布 f001–f091 |
| ST/SEG 银标准（可训练） | 92 帧 | 92 帧 |

细胞形态：面积中位数 **1789 px**，等效直径 **48 px**；质心最近邻距离中位数 **105 px（01）/ 116 px（02）**。

**关键测量：**

| 问题 | 实测 | 含义 |
|---|---|---|
| 细胞真的粘连吗？ | 把每个细胞膨胀 3 px 后与别的细胞接触的比例：**0/313（01）、0/380（02）= 0%** | 相邻核间距是核直径的 2 倍以上，"粘连合并"在这个数据上几乎不存在 |
| 亮度差异多大？ | 细胞平均亮度 **1.6–105**（约 60×）；01 的 p10/中位/p90 = 6.4/28.4/58.7，02 = 2.5/10.3/31.1 | 极暗细胞接近背景噪声，是主要难点 |
| 单阈值能做到多好？ | 扫 σ∈{2,3}、阈值 1–25、min-area∈{150,300}：**recall 上限 0.49**（thr=8, σ=2, minarea=300，precision 0.58） | 阈值法天花板就是漏一半，不用再试了 |

这三点合起来把问题定义换了：**GOWT1 是"低对比度核的检出与边界"问题，不是"HeLa 那种密集粘连"问题。**

## 3. 必须改的四处

### 3.1 错误分工表失效（最要紧）

原文映射是围绕 HeLa 的"细胞密集"设计的。用实测数据对一遍：

| 原文难点 | 原文归给 | 在 GOWT1 上的实测 | 结论 |
|---|---|---|---|
| 细胞密集，相邻核粘连被合并（NS） | #2、#3 | **0% 细胞接触** | 这块工作会做出"没有提升"，白费 |
| mitosis 时外观突变，分割出错（FN/FP） | #2 | 分裂只有 5 + 13 = **18 个事件** | 方向对，但样本极少，见 3.4 |
| 某帧漏检导致 track 断开（FN + EA） | #3 | 轨迹数 54 vs GT 28（01）、118 vs GT 58（02） | **成立，而且是最大的可改进项** |
| 密集区连错细胞（ID switch，EA/ED） | #4 | TRA − DET = **0.0013**（见 §4） | 几乎无空间，要换方向 |
| division 的 parent→daughter 漏连（EC） | #5 | 分裂召回 **1/5、2/13** | **成立，基线很低，容易做出提升** |

重写后的对应关系：

- **主错误 = FN（低对比度漏检）** → 分割灵敏度，归 #2，不是"密集区"归 #2/#3。
- **次错误 = 轨迹碎片化**（漏检帧把一条轨迹切成多条）→ 归 #3，用 gap closing + mask propagation。
- **第三 = division 边缺失**（EC）→ 归 #5，基线召回只有 8%–15%，空间很大。
- **NS（粘连合并）从表里删掉**，最多在 Discussion 里写一句"该数据不含此失效模式"。

### 3.2 训练预算：机器有 GPU，但显存只有 6 GB

先纠正一个前提：这台机器是 **RTX 3060 Laptop（6 GB 显存，驱动 610.62）**，但最初装的 torch 是 **CPU 版**（`2.14.1+cpu`），所以第一轮测出来的是纯 CPU 数字。现在 venv 里已换成 `torch 2.14.1+cu126`，`torch.cuda.is_available() == True`（主环境的 CPU 版未动）。

| 模型 | CPU（20 核） | GPU（RTX 3060 Laptop） |
|---|---|---|
| Cellpose 3 `nuclei`（25 MB） | 2.0–2.6 s/帧 | **0.46 s/帧** |
| Cellpose 4 `cpsam`（1.2 GB ViT） | 4 分钟没跑完 1 帧 | 未测（6 GB 显存需要分块） |

所以**推理完全够快**：整段 92 帧在 GPU 上约 **45 秒**跑完，反复试参数、跑消融都没问题。之前"CPU 不可行"的结论只对 CPU 成立，这里更正。

但两件事没变：

1. **训练预算要重新算**。6 GB 显存训 1024×1024 全图不现实，必须切 512 或 256 的 crop。
2. **Cellpose 4 只带 `cpsam` / `cpdino` 两个大模型，没有小模型**（`nuclei`/`cyto3` 是 3.x 时代的，我把版本锁在 3.1.1.2 就是因为这个）。要用它得下 1.2 GB 权重 + 分块推理，性价比不如自己训一个小 U-Net。

结论仍然成立，但原因变了：**不是"跑不动"，而是"五个人各训一个大模型的收益抵不上时间"**。ConvLSTM / LSTM tracker 在 86 条轨迹上训练仍然没意义——这是数据量问题，不是算力问题。

### 3.3 关键路径原本是串行的

原计划里 baseline 需要三个人先交付：#2 的 zero-shot + #4 的 Hungarian + #1 的 eval。任何一个人卡住，其余四人全部空转。

**这条现在已经消除了**：`src/track.py`（IoU + 匈牙利 + gap closing + 分裂检测）和 `src/evaluate.py`（官方 `py-ctcmetrics`）已经跑通并给出真实分数，baseline 是现成的。#4 可以直接从 association 改进开始（或者按 §4 换方向）。

### 3.4 notebook 合并会在最后一周爆掉

"每人自己的 notebook → 最后由 #1 合并"是最大的交付风险：五套环境、五个随机种子、五套输出路径，合并时还会遇到重复 import 和互相覆盖的变量。

改成：**逻辑全部放 `src/` 里（现在是这么做的），notebook 只调用函数**。每人负责一个 section 单元格，直接在同一个 notebook 里提交，全程只有一个 notebook 文件。这样 rubric 的"one notebook"是自然满足的，不是靠最后拼。

## 4. 我跑出来的基线（可以直接进 §5.1 主结果表）

命令链：`segment_cellpose` → `run_track` → `evaluate`，两个序列都跑满 92 帧，在 CPU 上约 4 分钟/序列（§4 末有调参对照）。

同一批结果里，比总分更有信息量的是这几条：

| 指标 | 01 | 02 | GT |
|---|---|---|---|
| 检出的轨迹数 | 54 | 118 | 28 / 58 |
| 检出的分裂数 | 1 | 2 | 5 / 13 |
| 预测细胞面积中位数 | 2768 px | 2782 px | 1789 px |

三条结论，都能直接写进 Results / Discussion：

1. **TRA − DET ≈ 0.0013（两个序列都是）** → 关联步骤几乎没有损失。
   换句话说，**当前系统的瓶颈 100% 在分割/检测，不在 tracker**。
2. **分裂召回 1/5 和 2/13** → division 是整个 pipeline 最薄弱的一环，也是 #5 的明确起点。
3. **预测面积比 GT 大 55%**（2768 vs 1789）→ SEG 只有 0.67 不是检出问题，是**边界画大了**。

第 3 条我去验了超参，结果**是一个值得写进报告的负面结果**，因为它差点误导我：

第一步，我只取 6 帧做参数扫描（贪心逐细胞 IoU），看起来调参有效：

| 设置 | 平均 IoU（6 帧） | 预测面积中位数 |
|---|---|---|
| 默认 cp=0, fl=0.4, diam=48 | 0.498 | 2612 |
| `diameter` 32→48 | 0.447→0.498 | 几乎不变 |
| cp=0, fl=1.0 | 0.533 | 1932 |
| **cp=3.0, fl=1.0** | **0.570** | 1905 |

第二步，把 cp=3/fl=1 跑满两个完整序列，用官方指标复核——**全面变差**：

| 设置 | DET 01 / 02 | SEG 01 / 02 | TRA 01 / 02 | 轨迹数 01 / 02 |
|---|---|---|---|---|
| 默认 cp=0, fl=0.4 | 0.8531 / 0.7563 | **0.6662 / 0.6827** | 0.8518 / 0.7550 | 54 / 118 |
| cp=3.0, fl=1.0 | 0.8214 / 0.6599 | **0.3589 / 0.4225** | 0.8195 / 0.6562 | 64 / 268 |

在 01 的全部 30 张金标帧上，逐细胞平均 IoU 也从 **0.674 掉到 0.402**（IoU<0.3 的细胞占比 22% → 40%）。

**教训（这条比调参本身值钱）：不要用"只对匹配上的细胞算 IoU"的代理指标调参。** 官方 SEG 是召回主导的——漏掉一个细胞，它的整块面积都算进误差；而逐细胞 IoU 会把"根本没检出来"的细胞记成 0 之后又被平均稀释，看起来还挺好。任何调参都必须在两个完整序列上用官方指标复核，这也是 rubric 里"error analysis"最想看到的那种反思。

**所以默认参数就是这个数据上的强基线**，SEG 0.67 的差距要靠改进模型/预处理（而不是阈值）来补。一个还没做的低成本实验：对默认 mask 做形态学腐蚀 2–4 px 再评 SEG（预测面积大 55%，腐蚀可能直接涨分），这是 #2 的第一炮。

## 5. "SOTA 已经很好，哪里还能提升" —— 有数据的答案

先说评分口径，避免大家在错误的目标上发力：**你们不需要打败 SOTA**。rubric 的 Results 3 分要的是"和 SOTA 对比 + 解释差异"，不是"超过 leaderboard"。而且 CTC leaderboard 是在不公开 test set 上算的，本来就不可直接比（你们原计划里也写了这点）。

真正能写、能被 markers 认定为"own work"的改进，按**实测损失大小**排序：

| 优先级 | 改进 | 证据 | 成本 |
|---|---|---|---|
| 1 | 低对比度核的预处理（局部背景扣除 / top-hat / 分块归一化） | 单阈值 recall 上限 0.49；亮度跨 60× | 极低，纯图像处理 |
| 2 | 分割边界（形态学后处理收缩 / 微调小 U-Net） | 面积偏大 55%；**阈值调参已证伪**（§4） | 中（小 U-Net 可 CPU 训练） |
| 3 | gap closing 修轨迹碎片化 | 54→28、118→58 条轨迹 | 极低，代码已有 `--max-gap`，扫一遍即可 |
| 4 | division 检测（母→两子） | 召回 1/5、2/13 | 中低（小 CNN 判 18 个事件） |
| 5 | 用 ST 银标准做自训练 / 半监督 | ST 有 92 帧，GT 只有 30/20 帧 | 中 |
| — | **LSTM tracker / ConvLSTM 时序修正** | TRA − DET = 0.0013 | **不建议**，没有空间 |

### 关于你说的"把后续训练层去掉再训练一次"

这个想法本身就是标准的 ablation，**而且是这个课题最值得做的那一个**。实测已经给了方向：TRA 比 DET 只低 0.0013，说明后面的关联层几乎不贡献分数。所以"去掉关联/时序层、只留分割"这一行消融，预期结论是：

> 系统性能由分割决定；去掉 learned association 后 TRA 下降 < 0.01，说明在稀疏、低运动的数据上，简单匈牙利关联已经饱和。

这正好把你们的"提升点"从"做一个更好的 tracker"转成"证明 tracker 不是瓶颈，把力气花在分割上"——**这是个诚实且更有说服力的结论**，而且省掉两个人的训练工作量。

## 6. 建议的分工（5 人，2 个训练模型）

| # | 负责 | 交付的可量化结果 | 训练成本 |
|---|---|---|---|
| 1 | EDA + 评测 + error breakdown + notebook 基础设施 | AOGM 六类错误分解表；EDA 三张图（亮度分布、间距分布、分裂时间线） | 无 |
| 2 | **分割改进**（对比度预处理 + 小 U-Net 微调，GT 与 GT+ST 对比） | SEG / DET 从 0.67/0.85 提升多少 | 一个小 U-Net，CPU 可训 |
| 3 | **时序/轨迹修复**（gap closing + mask propagation） | 轨迹数 54→28、TRA 提升多少；FN/EA 变化 | **无训练** |
| 4 | **SOTA 对照 + 压力测试**（Trackastra 零样本 / 人为降低检出率看关联何时失效） | 给出"关联在什么条件下才开始重要"的曲线 | 无训练（用预训练权重） |
| 5 | **分裂检测**（小 CNN 判 18 个事件） | division precision / recall、EC 数量 | 一个小 CNN |

改动要点：#4 从"训 LSTM"改成"对照 + 压力测试"，#3 从"训 ConvLSTM"改成"无训练的轨迹修复"。这样**只有两个人需要训练模型**，且都可以 CPU 完成。

## 7. 三个必须知道的坑

1. **01 的金标准分割只覆盖 f000–f047**。任何关于 01 后半段的 SEG 结论都没有标注支撑（TRA 是全覆盖的，DET/TRA 不受影响）。报告里要说清楚。

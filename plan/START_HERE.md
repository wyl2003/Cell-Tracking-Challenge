# 一页纸搞懂：这个项目在做什么

---

## 1. 一句话说明

给程序一段显微镜视频（92 张图，1024×1024），它要输出**两样东西**：

1. **每帧一张分割图**：图上每个细胞核涂成一个独立的编号，背景是 0。
2. **一张轨迹表**：每个细胞从第几帧活到第几帧、它的"母亲细胞"是谁。

就这两样。CTC 的比赛只评这两样。**不需要检测病灶、不需要分类、不需要诊断任何疾病。**

---

## 2. 为什么还要"轨迹表"

细胞在动，还会分裂。

* 第 5 帧的 7 号细胞和第 6 帧的 9 号，其实可能是**同一个细胞**（只是挪了位置）→ 程序必须知道它们是同一条轨迹，编号不能乱跳。
* 第 30 帧一个细胞裂成两个 → 表里要写清楚：母亲 7 在 29 帧结束，两个女儿 9、10 从 30 帧开始，且 `parent = 7`。

这张表就是 CTC 的 `man_track.txt`（标准答案）/ `res_track.txt`（你的答案），四列：

```
L  B  E  P      ← 编号  起始帧  结束帧  母亲编号（没有母亲就写 0）
```

---

## 3. 分数只看三个数（都在 0–1 之间，越高越好）

| 指标 | 在评什么 | 怎么算的直觉 |
|---|---|---|
| **SEG** | 分割有多准 | 逐像素比较：你的涂色和标准答案重合多少（Jaccard） |
| **DET** | 检出有多准 | 不看形状，只看"这个细胞你找到没有、位置对不对" |
| **TRA** | 整条轨迹有多准 | 把"漏检、误检、连错线、少连一条、多连一条、分裂连错"都算成罚分，归一化 |

TRA 的罚分是**加权的**（权重直接来自官方库源码 `ctc_metrics/metrics/technical/tra.py`）：

```
AOGM = 5·NS + 10·FN + 1·FP + 1·ED + 1.5·EA + 1·EC
TRA  = 1 − min(AOGM, AOGM₀) / AOGM₀        AOGM₀ = 10·顶点数 + 1.5·边数
```

| 错误 | 权重 | 含义 |
|---|---|---|
| **FN 漏检** | **10** | 最贵的一种 |
| NS 粘连未拆分 | 5 | |
| EA 少一条连接 | 1.5 | 轨迹断了 |
| FP 误检 | 1 | |
| ED 多一条连接 | 1 | 连错了 |
| EC 连接类型错 | 1 | 比如把分裂当成普通延续 |

所以**漏检一个细胞 = 十个误检的代价**。调参时宁可多检，不要漏检——这条在你们后面做阈值取舍时非常实用。

课程还会要你把错误拆开统计，缩写是：

| 缩写 | 意思 |
|---|---|
| FN | 漏检（该有没找到） |
| FP | 误检（不该有却找到了） |
| NS | 该拆成一个的粘连被合并了 |
| EA | 少了一条连接（轨迹断了） |
| ED | 多了一条连接（连错了） |
| EC | 连接类型错（把分裂当成普通延续） |

## 4. 金标准 / 银标准 —— 你最想搞清的那个

程序要学"哪个像素是细胞"，必须有人先告诉它答案。答案有两种：

| | **金标准 GT**（gold truth） | **银标准 ST**（silver truth） |
|---|---|---|
| 谁做的 | 人**逐像素手画**，专家复核 | **算法**从金标准传播/跟踪出来，再人工抽查 |
| 可信度 | 最高 | 大体对，边界和个别帧会有小错 |
| 覆盖范围 | **只有少数帧**（你们的数据：01 有 30 帧、02 有 20 帧） | **全部 92 帧** |
| 用途 | **打分**（SEG 只能在这些帧上算） | **训练模型**（数据量大），**不能用来打分** |
| 类比 | 考卷的标准答案 | 课后习题答案（全本，但可能有笔误） |

**最重要的一条规矩：不能用银标准给自己打分。** 它是算法生成的，拿它评分等于自己改卷子，分数会虚高，marker 一眼能看出来。

这解释了你们数据里的一个现象：`01_GT/SEG/` 只有 30 个文件，而 `01_ST/SEG/` 有 92 个。前者是打分用的题目，后者是补充练习。

正确用法：**训练用 GT + ST（数据多），报告分数只用 GT。**

## 5. 整条流水线只有 4 步

```
显微镜图 ──① 分割──> 每帧带编号的 mask
                          │
                          ├──② 关联──> 同一个细胞跨帧连起来
                          │
                          ├──③ 分裂检测──> 一个变两个的关系
                          │
                          └──④ 评测──> SEG / DET / TRA
```

* **① 分割**：每帧独立处理，把细胞核一个个圈出来。→ 决定 SEG
* **② 关联**：拿上一帧的编号去对下一帧，同一个细胞保持同一条轨迹。→ 决定轨迹是否断裂
* **③ 分裂**：认出"一个变两个"，并写进表的 P 列。→ 决定 EC
* **④ 评测**：把结果写成 CTC 格式，跑官方脚本。**这一步已经写好了，不用你们做。**

## 9. 五个不要踩的坑

1. **01 的金标准分割只覆盖 f000–f047**。别对 01 后半段下 SEG 结论，没有标注支撑（TRA 是全帧的，不受影响）。
2. **分裂只有 6 个事件**。一次错的权重是 16.7%，别画 PR 曲线，用逐事件表格。
2b. **`--max-gap > 0` 会让结果被 CTC 判为无效**，空档帧里必须有标签。
3. **别用"只对匹配上的细胞算 IoU"的代理指标调参**。我踩过：6 帧上看着从 0.50 涨到 0.57，跑满全序列 SEG 从 0.67 崩到 0.36。**一律用官方指标复核。**
4. **银标准不能评分**（见 §4）。
5. **数据集不能上传 GitHub**，`data/` 已经在 `.gitignore` 里。

## 10. 关于"测试集"

CTC 官网另有 test 序列（`_challenge` 包），但**它没有标准答案**——CTC 是让你跑完把结果发给组织方，由他们评分并在 leaderboard 上公布。所以：

* 只做课程项目 → **不需要 test 序列**，01/02 两折（01 训练 02 测试，再交换）完全够。
* 想上 leaderboard → 需要额外注册并向 CTC 提交，而且测试分数和你们在 01/02 上的分数**不可直接比较**（分布不同、且是隐藏 GT）。

同学发来的 test 包留着也行，但不是当务之急。
